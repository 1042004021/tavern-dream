## 2. Bug 描述

### 2.1 现象

模型正在输出回复时，向上滑动聊天记录会被立刻拉回底部，看不到前面内容；输出结束后才能正常滚动。

### 2.2 复现步骤

1. 进入任意角色对话。
2. 发送一条消息，等回复开始流式输出。
3. 在输出过程中向上滑动聊天区域。

### 2.3 预期 / 实际

- 预期：用户滑动后停在用户选择的位置，不再被强制跟随。
- 实际：每来一段增量文本就被瞬移回底部，滑动"弹回去"。

## 3. 影响分析

- 输出较长回复时无法回看前文，只能干等，阅读体验明显变差。
- 不影响消息数据与持久化。

## 4. 根因分析

`ChatScreen` 里的自动跟随逻辑：

```kotlin
LaunchedEffect(vm.messages.size, vm.streamingText.length) {
    runCatching { listState.animateScrollToItem(visualCount - 1) }
}
```

监听的是 `streamingText.length`，模型每吐一段增量都会触发一次，无条件滚动到最后一项，把用户的滚动位置覆盖掉。

## 5. 修复方案

1. 用 `snapshotFlow { listState.layoutInfo }` 记录「用户是否已在底部」（允许 1~2 项误差，避免新消息插入瞬间误判）。
2. 只有 `atBottom == true` 时才自动跟随；用户上滑后 `atBottom` 变 false，不再抢位置。
3. 新消息用 `animateScrollToItem` 平滑滚动，流式增量用 `scrollToItem` 直接跟，避免频繁动画互相打断。
