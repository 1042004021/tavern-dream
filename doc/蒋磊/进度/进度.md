## 4. 风险与阻塞

| 编号 | 内容 | 影响 | 应对 |
|---|---|---|---|
| R01 | GitHub Release 下载极慢（单连接 ~5KB/s） | 提取 native 库耗时 | 已用 16 分片并行 + gh-proxy 完成 |
| R02 | 无骁龙真机 | NPU 路径无法实测 | 保留 CPU 模型作为兜底 |
| R03 | 模型 1.1GB | 首次使用门槛 | App 内下载；实测 huggingface.co 不通，默认源改为 hf-mirror.com |
| R04 | 本地 4B 模型约 3GB 内存 | 与生图不能并存 | 生图前自动卸载；另提供 Qwen3-1.7B 轻量档 |
| R05 | 无真机 | 本地推理的加载耗时、token/s、内存峰值均未实测 | 已在 SM8750/12GB 实机跑通，数据见 Task02「实测数据」 |
| R07 | 生图在部分 ROM 上 QNN 无签名 PD 被拒（`createUnsignedPD ... not supported by HTP`） | NPU 生图可能不可用 | 实测 App 内直连可正常创建 QNN 设备；若某机型被拒，保留 CPU 生图模型兜底 |
| R06 | 4B 模型内存峰值约 3.2GB，实机出现系统 LMK 回收后台应用（微信/QQ/GMS） | 同时开其他 App 时体验受影响 | 1.7B 档只需 2.0GB；生图前自动卸载；后续可考虑降线程数或改 Q4 更小模型 |
| R08 | SDXL 端侧 PSS 5.5GB，12GB 机型触发 LMK 并重启 | 大模型生图不可用 | 放弃 SDXL，改用 SD 2.1（约 1.3GB / 768 原生 / v-pred） |
| R09 | 设备不在手边 | v0.4.1 无法真机验证 | 代码已构建通过，等设备返回后按 Task06 第 5 节逐项验证 |
| R10 | SD 2.1 在 768×576 出噪声，仅 512 可用 | 横图质量受限 | 已确认：512 原生 + 4:3 裁切 + 4x 超分可用，768 出噪声暂放弃 |
| R11 | 自动配图把角色名当题材（角色叫 Cricket，出图变成板球运动场） | 配图与角色形象不符 | 提示词链路把角色名一起喂给 SD；后续可考虑从提示词里剔除角色名、只留外貌描述 |
| R13 | 人物脸无法真正锁定 | 同一角色每张脸会有差异 | 内核无 IP-Adapter/ControlNet，运行时 LoRA 无入口；`xororz/SD21` 也不提供 vae_encoder，img2img 走不通。当前只能靠「外观锚定 tag + 固定种子 + 固定画风 tag」近似 |
| R12 | SD 2.1 出图约 45 秒（含引擎启动） | 自动配图有等待感 | 引擎常驻时可缩短到 10 秒内；后续可考虑对话结束就先预热 |
