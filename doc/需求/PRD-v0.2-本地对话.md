# PRD v0.2 - 本地对话（离线 LLM）

## 1. 背景

v0.1 的对话只有「外部 OpenAI 兼容 API」一条路，断网或不想填 Key 就用不了。
v0.2 增加一条**完全离线**的本地对话通道，与 API 通道并存，设置里可切换。

## 2. 目标

- 一个 APK 内同时具备：角色卡、对话（双通道）、本地生图。
- 本地对话不依赖网络、不依赖任何外部服务。
- 与生图共存但**不同时占用内存**（生图前自动卸载本地模型）。

## 3. 范围

| 项 | 内容 |
|---|---|
| 新增 | 本地对话引擎（MNN-LLM）、本地模型下载、双通道切换 |
| 不改 | 角色卡导入、会话存储、生图流程、提示词组装 |

## 4. 方案

### 4.1 推理框架

| 候选 | 结论 |
|---|---|
| **MNN-LLM（阿里）** | **采用**：与 local-dream 的 CPU 生图后端同源；官方已放出 Qwen3 的 MNN 格式权重；MNN Chat 开源可参考 |
| llama.cpp | 中文生态好，但要自己交叉编译 + JNI 封装，模型还要另找 GGUF |
| MediaPipe / LiteRT-LM | 集成最省事，但只支持 Gemma，中文角色扮演弱一档 |

### 4.2 模型

| 模型 | 仓库 | 体积 | 说明 |
|---|---|---|---|
| **Qwen3 4B**（默认） | `taobao-mnn/Qwen3-4B-MNN` | 2.6GB | 中文角色扮演首选；官方 MNN 格式，免转换 |
| Qwen3 1.7B | `taobao-mnn/Qwen3-1.7B-MNN` | 1.2GB | 轻量备选，速度更快、效果弱一些 |

模型不打进 APK，运行时从 HuggingFace（默认 `hf-mirror.com`）按文件下载。

### 4.3 硬约束（已向老大交底）

| 项 | 现实 |
|---|---|
| 存储 | SD 模型 1.1GB + LLM 2.6GB ≈ 4GB |
| 内存 | 4B 约需 3GB 可用内存，**与生图不能同时跑** |
| 速度 | 手机 CPU 推理个位数 token/s，明显慢于云端 API |
| 质量 | 4B 本地模型与云端大模型有实打实的差距 |

## 5. 交互

1. 设置 → 对话引擎：`外部 API` / `本地模型（离线）` 二选一。
2. 选本地后：选模型 → 下载 → 首次对话自动加载（10~30 秒）→ 流式出字。
3. 状态显示：未下载 / 下载中 / 加载中 / 已加载 / 失败原因。
4. 点「生图」时自动卸载本地模型腾内存。

## 6. 验收标准

1. 断网、不填 API Key 时，仍能完整对话。
2. 切换回 API 后行为与 v0.1 一致。
3. 模型下载可断点续传（已存在且大小一致的文件跳过）。
4. 下载失败、加载失败都有明确提示，不闪退。
5. 生图与本地对话不会同时占用内存。

## 7. 风险

| 编号 | 内容 | 应对 |
|---|---|---|
| R04 | 首次加载 2.6GB 权重耗时较长 | 常驻内存，切角色不重载；界面提示「加载中」 |
| R05 | 低内存机型被系统杀后台 | 仅保留 Qwen3-1.7B 轻量档；生图前主动卸载 |
| R06 | Qwen3 默认开启思考模式，污染角色扮演输出 | `runtime.json` 里注入 `jinja.context.enable_thinking=false` |
| R07 | 本地模型输出速度慢，用户误以为卡死 | 流式输出 + 「正在思考」状态提示 |
