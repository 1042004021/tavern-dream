## 2. 需求概述

### 2.1 背景

1. 自动配图靠 `<imagine>` 约定，但模型几乎不主动输出，用户实际从未触发过自动出图。
2. 每次出图人物长相、画风不统一；且提示词里带了角色名，SD 把名字当题材（角色叫 Cricket → 画出板球运动场）。
3. 进入角色卡直接开始剧情，玩家不知道自己扮演谁、世界观是什么。

### 2.2 目标

| 编号 | 目标 |
|---|---|
| G1 | 出图人物外观与画风尽量统一 |
| G2 | 由对话模型判断场景是否变化，只在该出图时出图 |
| G3 | 输入框旁提供「生图」按钮，可随时按当前剧情出一张 |
| G4 | 进入角色卡时给出世界观、玩家身份、当前场景 |

### 2.3 范围

- 做：外观锚定 tag、场景变化判断、生图按钮、开局设定卡、角色名剔除、固定种子开关。
- 不做：IP-Adapter / ControlNet / 角色 LoRA（端侧内核不支持，见 Task07 风险项）。

## 3. 功能需求

| 编号 | 功能 | 说明 | 验收标准 |
|---|---|---|---|
| F1 | 外观锚定 | 首次进入角色时生成一组英文外观 tag 并缓存，之后每张图都带上 | 同一角色两次出图人物特征一致度明显提升；设置可关闭 |
| F2 | 场景变化判断 | 系统提示要求模型只在换地点/换时间/新角色/大转折时输出 `<imagine>` | 闲聊不重复出图；换场景会出图 |
| F3 | 生图按钮 | 输入框左侧 🎨 按钮，总结最近对话出图 | 点击后出图并插入对话 |
| F4 | 开局设定卡 | 聊天顶部卡片显示世界观 / 你扮演谁 / 当前场景 | 首次进入自动生成，可折叠，可重新生成 |
| F5 | 角色名剔除 | 提示词中删除角色名 | 出图不再出现"名字变题材" |
| F6 | 固定种子 | 可选开关，同一角色固定 seed | 开启后构图接近、脸更稳 |

## 4. 非功能需求

- 设定与外观 tag 每角色只生成一次，缓存到 `characters/<id>/meta.json`，重复进入不消耗额度。
- 出图失败不阻塞对话。
- 关闭思考模式后，设定生成单次约 3~6 秒。
